**不建议集成**。原因如下：

## 边缘设备资源限制分析

| 资源类型 | Baseline 消耗 | 边缘设备影响 |
|---------|--------------|-------------|
| **CPU** | 每次计算需要遍历历史数据 | 高，边缘设备 CPU 通常 1-4 核 |
| **内存** | 加载历史到内存 + 缓存基线 | 高，边缘设备内存 128-512MB |
| **存储 I/O** | 频繁查询历史数据库 | 中，数据库和实时写入竞争 |
| **延迟** | 每次分析前需计算阈值 | 高，影响实时性 |

## 边缘 vs 云端 适用性对比

| 场景 | 固定阈值（当前） | 动态阈值（Baseline） |
|------|----------------|-------------------|
| 边缘设备 | ✅ 零计算，立即判断 | ❌ 需要历史计算 |
| 云端分析 | ❌ 无法自适应 | ✅ 智能学习 |
| 设备刚接入 | ✅ 可配置默认值 | ❌ 无历史数据 |
| 环境变化 | ❌ 需手动调整 | ✅ 自动适应 |

## 建议：保持解耦，云端计算

```
边缘设备 ──── 实时分析（固定阈值） ──── 快速告警
    │
    │ 定期上传历史数据
    ↓
云端服务 ──── Baseline 计算 ──── 下发动态阈值
    │
    ↓
边缘设备 ──── 使用下发的阈值 ──── 无需本地计算
```

**结论**：在边缘资源受限场景下，保持当前设计，`Baseline` 更适合在**云端/管理节点**运行后下发配置。
