## 1. 概述

资源配额与多租户隔离是 sfsEdgeStore 企业版的核心功能之一，旨在解决边缘设备资源受限的问题。通过限流和超时控制等机制，确保系统在资源有限的情况下稳定运行，防止单个采集任务占用过多资源，影响其他任务的正常执行。

## 2. 核心功能

### 2.1 限流

在采集模块增加令牌桶算法，限制每个设备的最大采集频率，防止高频采集占用过多 CPU 资源。

**实现方式：**
- 使用令牌桶算法控制采集频率
- 为每个设备设置独立的限流配置
- 支持动态调整限流参数

**配置示例：**
```yaml
devices:
  - name: "temp-sensor"
    driver: "modbus"
    address: "192.168.1.100:502"
    register: 0
    rate_limit: 10  # 每秒最多采集 10 次
```

### 2.2 超时控制

任何 Modbus/OPC 读取操作，必须有强制超时，防止因为设备故障导致整个软件卡死。

**实现方式：**
- 为每个采集操作设置超时时间
- 使用 context 控制操作超时
- 超时后自动重试或跳过

**配置示例：**
```yaml
devices:
  - name: "temp-sensor"
    driver: "modbus"
    address: "192.168.1.100:502"
    register: 0
    timeout: 2  # 超时时间（秒）
    retries: 3  # 重试次数
```

### 2.3 多租户隔离

在多租户场景下，确保不同租户的资源使用相互隔离，防止单个租户占用过多资源。

**实现方式：**
- 为每个租户设置资源配额
- 监控每个租户的资源使用情况
- 当资源使用超过配额时进行限制

**配置示例：**
```yaml
# 多租户配置
tenants:
  - name: "tenant1"
    resources:
      cpu_limit: 50  # CPU 使用率限制（%）
      memory_limit: 512  # 内存限制（MB）
     采集频率限制: 100  # 每秒最大采集次数
  - name: "tenant2"
    resources:
      cpu_limit: 30
      memory_limit: 256
     采集频率限制: 50
```

## 3. 实现细节

### 3.1 限流实现

使用令牌桶算法实现限流：

**核心代码示例：**
```go
// rate_limiter.go
package rate

import (
	"time"
)

// RateLimiter 速率限制器
type RateLimiter struct {
	rate       float64   // 每秒生成令牌数
	capacity   float64   // 令牌桶容量
	tokens     float64   // 当前令牌数
	lastUpdate time.Time // 上次更新时间
}

// NewRateLimiter 创建速率限制器
func NewRateLimiter(rate, capacity float64) *RateLimiter {
	return &RateLimiter{
		rate:       rate,
		capacity:   capacity,
		tokens:     capacity,
		lastUpdate: time.Now(),
	}
}

// Allow 检查是否允许操作
func (rl *RateLimiter) Allow() bool {
	now := time.Now()
	duration := now.Sub(rl.lastUpdate)
	rl.lastUpdate = now

	// 生成新令牌
	rl.tokens += duration.Seconds() * rl.rate
	if rl.tokens > rl.capacity {
		rl.tokens = rl.capacity
	}

	// 消耗令牌
	if rl.tokens >= 1 {
		rl.tokens--
		return true
	}

	return false
}
```

### 3.2 超时控制实现

使用 context 实现超时控制：

**核心代码示例：**
```go
// timeout.go
package timeout

import (
	"context"
	"time"
)

// WithTimeout 带超时的函数执行
func WithTimeout(f func() error, timeout time.Duration) error {
	ctx, cancel := context.WithTimeout(context.Background(), timeout)
	defer cancel()

	// 使用通道执行函数
	errCh := make(chan error, 1)
	go func() {
		errCh <- f()
	}()

	// 等待结果或超时
	select {
	case err := <-errCh:
		return err
	case <-ctx.Done():
		return ctx.Err()
	}
}
```

### 3.3 多租户隔离实现

**核心代码示例：**
```go
// tenant.go
package tenant

import (
	"sync"
)

// Tenant 租户
type Tenant struct {
	Name      string
	CPULimit  int     // CPU 使用率限制（%）
	MemLimit  int     // 内存限制（MB）
	RateLimit int     // 采集频率限制
	usage     Usage
	mu        sync.Mutex
}

// Usage 资源使用情况
type Usage struct {
	CPU    int
	Memory int
	Rate   int
}

// CheckResource 检查资源使用情况
func (t *Tenant) CheckResource() bool {
	t.mu.Lock()
	defer t.mu.Unlock()

	return t.usage.CPU <= t.CPULimit &&
		t.usage.Memory <= t.MemLimit &&
		t.usage.Rate <= t.RateLimit
}

// UpdateUsage 更新资源使用情况
func (t *Tenant) UpdateUsage(usage Usage) {
	t.mu.Lock()
	defer t.mu.Unlock()

	t.usage = usage
}
```

## 4. 配置与使用

### 4.1 配置文件

在 `config.yaml` 文件中配置资源配额：

```yaml
# 资源配额配置
resource_quota:
  enabled: true
  default_rate_limit: 10  # 默认采集频率限制
  default_timeout: 2      # 默认超时时间（秒）
  default_retries: 3      # 默认重试次数

# 多租户配置
tenants:
  - name: "tenant1"
    resources:
      cpu_limit: 50
      memory_limit: 512
      rate_limit: 100
```

### 4.2 命令行工具

使用 `sfs-cli` 命令行工具管理资源配额：

```bash
# 查看资源使用情况
sfs-cli resource status

# 设置资源配额
sfs-cli resource set --tenant tenant1 --cpu-limit 50 --memory-limit 512

# 查看租户列表
sfs-cli tenant list
```

## 5. 最佳实践

1. **合理设置限流**：根据设备性能和网络状况，设置合理的采集频率限制
2. **超时设置**：为不同类型的设备设置合适的超时时间，避免因设备响应慢导致系统卡死
3. **资源监控**：定期监控系统资源使用情况，及时调整资源配额
4. **多租户管理**：为不同租户设置合理的资源配额，确保资源使用公平
5. **异常处理**：当资源使用超过配额时，采取适当的处理措施，如降低采集频率或暂停部分任务
