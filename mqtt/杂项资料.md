好问题！这是因为 MQTT 的 **CleanSession** 设置。

## 两种方案对比

| 方案 | CleanSession | 订阅恢复 | 说明 |
|------|-------------|---------|------|
| **当前** | `true`（新建会话） | ❌ 需要手动恢复 | 重连后订阅丢失 |
| **替代** | `false`（持久会话） | ✅ 自动恢复 | broker 自动保持会话 |

## 当前代码

```go
opts.SetCleanSession(true)  // 每次连接创建新会话
```

| 时机 | 行为 |
|------|------|
| 连接成功 | `Subscribe()` 订阅主题 |
| 异常断开 | broker 清除会话，订阅丢失 |
| 重连成功 | `onConnect` 回调调用 `restoreSubscriptions()` 重新订阅 |

## 简化方案

如果设置 `CleanSession: false`：

```go
opts.SetCleanSession(false)  // 持久会话
opts.SetAutoReconnect(true)
```

| 时机 | 行为 |
|------|------|
| 连接成功 | broker 自动恢复之前的订阅 |
| 不需要 | `restoreSubscriptions()` 手动恢复 |

---

## 结论

**你希望哪种方案？**

1. **保持当前**（`CleanSession=true` + 手动恢复）- 更可控
2. **简化**（`CleanSession=false`）- 更简单，不需要 `restoreSubscriptions()`

这是调用 **paho-mqtt** 库的 `Subscribe` 函数，用于订阅 MQTT 主题。

## 参数详解

```go
token := c.client.Subscribe(
    topic,         // 参数 1: 要订阅的主题
    1,             // 参数 2: QoS (服务质量)
    c.onMessage    // 参数 3: 消息到达时的回调函数
)
```

## QoS 级别

| 值 | 含义 | 说明 |
|----|------|------|
| 0 | At most once | 最多一次，可能丢消息 |
| 1 | At least once | 至少一次，保证送达（当前使用） |
| 2 | Exactly once | 精确一次，性能稍低 |

## 完整流程

1. **调用 Subscribe** → paho-mqtt 发送订阅请求到 broker
2. **Broker 确认** → token.Wait() 等待完成
3. **消息到达** → broker 转发消息，调用 `c.onMessage` 回调

## 对应代码

```go
func (c *MQTTClient) Subscribe(topics []string) error {
    for _, topic := range topics {
        if c.subscribed[topic] {
            continue // 已订阅则跳过
        }
        
        // 订阅主题，QoS=1
        token := c.client.Subscribe(topic, 1, c.onMessage)
        token.Wait() // 等待订阅确认
        
        if token.Error() != nil {
            return token.Error()
        }
        
        c.subscribed[topic] = true
    }
    return nil
}
```

## 回调函数

```go
opts.SetOnConnectHandler(c.onConnect)     // 连接成功回调
opts.SetConnectionLostHandler(c.onConnectionLost) // 连接断开回调
```

当消息到达时，`c.onMessage` 会被自动调用。
