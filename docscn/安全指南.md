# 安全指南

sfsEdgeStore 认证、TLS 和授权说明。

## 数据主权

sfsEdgeStore 采用**本地优先架构**，确保**完全的数据主权**：

- **不依赖云端**：所有数据存储在本地边缘设备上
- **无跨境传输**：数据永不离开您的场所，符合 GDPR、欧盟《网络弹性法案》等数据驻留法规
- **零第三方暴露**：除非显式配置，否则不会向外部服务发送任何数据
- **完全控制**：您拥有硬件、软件和数据

这对于欧洲和其他隐私法规地区处理敏感工业数据的行业是一个**关键差异化优势**。

## 静态数据加密

### 数据库加密

sfsEdgeStore 支持 AES-256 加密磁盘上的数据：

```json
{
  "db_use_encryption": true,
  "db_encryption_key": "your-encryption-key",
  "db_encryption_algorithm": "aes-256-gcm"
}
```

**为什么这对 GDPR 合规很重要：**
- 数据在边缘设备上以加密状态存储
- 即使物理设备被盗，数据仍然不可读
- 您控制加密密钥——无需第三方密钥管理
- 加密是可选的，非敏感部署可以禁用

### API Key 认证

sfsEdgeStore 支持基于 API Key 的认证，用于保护敏感端点。

#### 创建 API Key

```bash
curl -X POST http://localhost:8081/api/auth/create-key
```

#### 列出 API Keys

```bash
curl http://localhost:8081/api/auth/list-keys
```

#### 撤销 API Key

```bash
curl -X POST http://localhost:8081/api/auth/revoke-key
```

### RBAC（基于角色的访问控制）

sfsEdgeStore 实现基于角色的访问控制，包含以下角色：

| 角色 | 权限 |
|------|------|
| 管理员 | 所有 API 完全访问 |
| 查看者 | 数据和指标只读访问 |
| 操作员 | 只读访问 + 备份/恢复操作 |

## TLS/SSL

### MQTT TLS

加密 MQTT 通信：

```json
{
  "mqtt_use_tls": true,
  "mqtt_ca_cert": "/etc/ssl/certs/ca.pem",
  "mqtt_client_cert": "/etc/ssl/certs/client.pem",
  "mqtt_client_key": "/etc/ssl/private/client.key"
}
```

### HTTP TLS（HTTPS）

加密 HTTP 通信：

```json
{
  "http_use_tls": true,
  "http_cert": "/etc/ssl/certs/server.pem",
  "http_key": "/etc/ssl/private/server.key"
}
```

## 安全最佳实践

1. **启用 TLS** - MQTT 和 HTTP 通信都使用 TLS
2. **使用 API Key** - 保护敏感 API 端点
3. **加密数据库** - 敏感数据启用数据库加密（工业数据 GDPR 合规必需）
4. **定期轮换密钥** - 定期轮换加密密钥和 API Key
5. **限制访问** - 使用 RBAC 基于角色限制访问
6. **监控日志** - 查看日志中的可疑活动
7. **保持更新** - 及时应用安全更新
8. **本地优先部署** - 数据保留在边缘设备上，避免不必要的云同步

## GDPR 合规检查清单

欧洲部署请确保以下配置：

- [ ] 启用数据库加密（`db_use_encryption: true`）
- [ ] 将加密密钥保存在安全位置
- [ ] 为所有通信启用 TLS（MQTT + HTTP）
- [ ] 配置数据保留策略（`enable_retention_policy: true`）
- [ ] 限制对边缘设备硬件和网络的访问
- [ ] 记录数据处理活动（设备类型、收集的数据）
- [ ] 为静态数据备份配置加密
- [ ] 审查并限制数据同步到批准的目的地
