# 告警中心数据来源分析

您的理解是正确的！告警中心的主要数据确实是通过设备配置文件（如 `pressure_sensor.yml`）中定义的阈值来生成的。让我详细分析一下这个过程：

## 设备配置文件的作用

设备配置文件（如 `pressure_sensor.yml`）定义了设备的：
- **基本信息**：设备名称、制造商、型号
- **设备资源**：如压力（pressure）、温度（temperature）
- **资源属性**：
  - 数据类型（valueType）
  - 最小值（minimum）
  - 最大值（maximum）
  - 默认值（defaultValue）
  - 单位（units）

## 告警生成流程

1. **设备配置加载**：
   - 系统启动时，`device.GetProfileManager().LoadProfiles("device_profiles")` 加载所有设备配置文件
   - 每个设备配置文件被解析为设备配置对象

2. **数据处理**：
   - `messageHandler` 函数处理 MQTT 消息，提取设备数据
   - 数据经过过滤后存储到数据库
   - 同时，数据被传递给数据分析器

3. **数据分析**：
   - 数据分析器使用设备配置文件中定义的阈值来分析数据
   - 当数据超出阈值时，生成相应的告警
   - 例如，当温度超过 `maximum` 值时，生成 "温度超限" 告警

4. **告警推送**：
   - 生成的告警通过 WebSocket 推送到前端
   - 前端更新告警中心和问题设备列表

## 系统资源告警的问题

系统资源相关的告警（如 "CPU使用超限"、"内存使用超限"）是由 `ResourceMonitor` 生成的，与设备数据无关。这些告警会干扰告警中心的主要功能，因为：

1. **与设备监控无关**：系统资源告警属于系统管理范畴，不属于设备监控
2. **频繁误报**：默认阈值设置较低，容易触发误报
3. **信息冗余**：系统资源使用情况已经在仪表盘的其他部分显示

## 解决方案

我已经实施了以下解决方案：

1. **移除系统资源告警生成**：
   - 从 `resource/monitor.go` 中移除了 `checkMemory` 和 `checkCPU` 函数中的告警生成逻辑
   - 保留了资源使用监控的日志记录和资源调整逻辑

2. **过滤系统资源告警**：
   - 在 `monitor/monitor.go` 的 `GetAlertGroups` 函数中添加了过滤逻辑
   - 使用 `sfsAlert.IsSystemResourceAlert` 函数跳过系统资源相关的告警

3. **移除告警模板**：
   - 从 `alertMessageTemplates` 映射中移除了系统资源相关的告警类型

## 效果

现在告警中心应该只显示与设备相关的告警，如：
- 温度超限
- 湿度超限
- 数据异常
- 设备离线/上线
- 数据趋势异常

这些告警都是基于设备配置文件中定义的阈值生成的，与设备实际运行状态直接相关，为用户提供了有价值的设备监控信息。
